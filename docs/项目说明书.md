## 一、这个项目是做什么的

**一句话**：一个「毒蛇咬伤自救科普」的全栈系统——手机 App 给普通用户用（认蛇、自救、找医院、答题学知识），网页管理后台给管理员用（维护蛇种库、题库、文章、审核咨询），后端提供全部 API。

这是一个**毕业设计项目**（根目录 `毕设选题需求说明.doc` 是原始需求文档），所以代码里有很多教学性设计：分层清晰、注释较多、功能覆盖面广。

### 三端一览

| 端 | 目录 | 技术 | 给谁用 | 访问方式 |
|---|---|---|---|---|

## 三、系统架构与请求链路（⭐ 最重要的一节，看懂这个就看懂了一半）

### 全链路一张图

```
┌─────────────┐   ①HTTP 请求    ┌──────────────────┐   ③转发     ┌────────────────┐
│  浏览器/手机  │ ─────────────→ │   中间转发层(谁?)  │ ─────────→ │ 后端 :8080/api  │
└─────────────┘                └──────────────────┘            └───────┬────────┘
                                                                       │ ④JDBC
   「中间转发层」按运行方式不同，有三种：                                 ▼
   A. H5 开发：vite dev server（proxy 配置）                      ┌──────────┐
   B. H5 上线：nginx（管理台容器内，proxy_pass）                    │  MySQL   │
   C. App 真机：没有中间层，App 直连后端                            └──────────┘
```

### 三端地址策略对照表（新手最容易搞晕的地方，请背下来）

| 运行场景 | 页面里的地址长什么样 | 谁把它变成真正的后端地址 | 最终去向 |
|---|---|---|---|
| **H5 开发**（浏览器开 localhost:5173） | `API_BASE = ''`（空字符串=相对路径） | **vite proxy**（`vite.config.js` 的 `server.proxy`，4 条规则） | `http://localhost:8080` |
| **H5/管理台上线**（nginx 部署） | `baseURL = '/api'`（相对路径） | **nginx**（`snake-admin-web/nginx.conf` 的 `proxy_pass`） | `http://snake-backend:8080`（容器名，Docker 内部 DNS） |
| **App 真机** | `API_BASE = 'http://localhost:8080'`（写死的完整地址） | 没有中间层，直接发 | ⚠️ 手机上的 `localhost` 指手机自己，真机调试必须改成**电脑的局域网 IP**（如 `192.168.1.105`） |

**为什么这样设计？**

1. **H5 用相对路径**：浏览器从 `localhost:5173` 页面直接请求后端属于**跨域**，而后端没有配 CORS 会被浏览器拦截。用相对路径 + 代理转发，浏览器眼里前后端"同源"，天然没有跨域问题。
2. **App 必须写完整地址**：App 是装在手机上的独立程序，没有 vite 也没有 nginx 帮它转发，只能直连。默认值 `localhost` 只在"跑在同一台设备上"时成立，所以真机调试要改成电脑 IP。

### 统一入口：utils/api.js

全项目所有接口地址都从这一个文件来（这就是为什么改服务器地址只用改它）：

```js
// snake-aid-app/utils/api.js
function detectBaseUrl() {
  // #ifdef H5          ← 条件编译：只在编译 H5 时保留
  return ''            //    相对路径，交给 vite/nginx 代理
  // #endif
  // #ifdef APP-PLUS    ← 条件编译：只在编译 App 时保留
  return 'http://localhost:8080'   //    真机调试要改成电脑局域网 IP
  // #endif
}
export const API_BASE = getBaseUrl() + '/api'
```

> `// #ifdef XXX ... // #endif` 是 uni-app 的**条件编译**语法：编译成 H5 时 `APP-PLUS` 段被删掉，编译成 App 时 `H5` 段被删掉。同一份源码，产出两种不同的程序——这是 uni-app 跨端的核心机制。

**页面里怎么用**（22 个页面都是这个写法）：

```js
import { API_BASE } from '@/utils/api'
const res = await fetch(`${API_BASE}/snake/list`)
```

### 数据流向实例：手机上打开"就近医院"

```
手机 App
  → GET http://localhost:8080/api/hospital/nearby   (直连后端)
  → Docker Desktop 把 8080 转进容器
  → snake-backend (Spring Boot) 收到，路由 HospitalAppController
  → 查 MySQL snake 库 hospital 表
  → 返回 JSON
  → 页面渲染
```

## 五、后端详解（snake-aid-backend）

### 分层架构（请求的旅程）

```
HTTP 请求
  → controller/    接收参数、参数校验（薄层，尽量不写业务逻辑）
  → service/       业务逻辑（事务、规则、组装）
  → mapper/        数据库操作（MyBatis-Plus 的 BaseMapper 提供单表 CRUD，
                   复杂 SQL 写在 resources/mapper/*.xml）
  → entity/        与表一一对应的 Java 类
  → 统一返回 JSON（common 包的 Result 类包装，永远是 {code, message, data} 结构）
```

### Controller 双轨制（33 个，命名看后缀）

| 后缀/位置 | 数量 | 给谁调 | 鉴权方式 |
|---|---|---|---|
| `XxxAppController`（`controller/app/`） | 16 | 手机 App | JWT 令牌（登录后请求头带 token） |
| `XxxAdminController`（`controller/admin/`） | 17 | 管理后台 | Spring Security 账号密码登录 |
| `FileUploadController` | 1 | 两端都用 | 文件上传，返回 `/uploads/...` 路径 |

功能覆盖：认证登录、蛇种、医院、血清库存、急救指引、文章、并发症、科普视频、题库/测验、积分、病历、咨询工单、AI 对话、严重程度评估、区域、统计、操作日志、审计。

### 数据表（约 25 张，完整以 `snake-aid-backend/docs/sql/` 为准）

| 分组 | 表 |
|---|---|
| 用户与账号 | `app_user`(App用户) `sys_user`(后台管理员) `region`(省市区) |
| 蛇种内容 | `snake_species` `snake_image` `first_aid_guide` `first_aid_step` `article` |
| 医疗资源 | `hospital` `serum_stock`(血清) |
| 题库测验 | `question` `user_quiz` `user_quiz_detail` |
| 积分成长 | `user_points_log` `level_config`(等级规则) |
| 咨询与AI | `consultation_ticket` `consultation_message` `ai_chat_history` |
| 运维审计 | `operation_log`(管理端操作) `audit_record` `access_statistics` `content_version` |

**初始化机制**：`docs/sql/*.sql` 挂载到 MySQL 容器的 `/docker-entrypoint-initdb.d/`，**只在数据卷为空的第一次启动时自动执行**。之后再改 SQL 不会重新执行（要清库重来才会）——测试新 SQL 可以手动 `docker exec -i snake-mysql mysql -uroot -p... snake < xxx.sql`。

### 关键机制速查

- **JWT 认证**：App 登录 → `AuthAppController` 签发 token（24 小时）→ 之后每个请求头带 `Authorization: Bearer xxx` → `security/` 里的过滤器校验。密钥来自 `JWT_SECRET` 环境变量。
- **操作日志**：管理端任何写操作被 `aspect/` 的切面自动记录到 `operation_log`——不用手写日志代码。
- **API 文档**：启动后访问 `http://localhost:8080/api/doc.html`（Knife4j），调试接口首选，不用 Postman 也能发请求。
- **文件上传**：存进 `snake-uploads` 卷（容器内 `/app/uploads`），nginx 把 `/uploads` 路径反代给后端读取。上传大小限制 250m（在 `nginx.conf` 里，超了报 413）。

### 它为什么从不跨域：nginx 反代

管理台的请求全部写成**相对路径** `/api/xxx`，浏览器发给同一台机器的 nginx，nginx 再转给后端容器：

```nginx
# snake-admin-web/nginx.conf
location /api/ {
    proxy_pass http://snake-backend:8080;   # ← Docker 服务名，容器间内部DNS
}
client_max_body_size 250m;                   # ← 上传文件的大小上限
```

`snake-backend` 是 compose 里的服务名，Docker 内网自动把它解析成后端容器 IP。**⚠️ 千万别把这个改成 `192.168.1.x` 或 `localhost`**——nginx 本身跑在容器里，改了它就找不到后端了（直接 502）。

## 七、本地开发指南（按场景照做即可）


### 场景 B：打开管理后台

```powershell
docker logs -f snake-backend              # 看启动日志，出现 Started 即成功
```

IDE 里调试（打断点）不走容器：本地装 JDK17 + Maven，把 `application.yml` 的 DB 地址改成 `127.0.0.1:3307`、Redis 改 `127.0.0.1:6379`（这两个端口只绑本机回环，正好本地调试用），直接运行启动类即可。

### 场景 D：真机跑 App（手机连电脑）

1. 把 `utils/api.js` 的 APP-PLUS 地址改成**电脑的局域网 IP**（默认是 `localhost`，手机上访问不到电脑；`ipconfig` 查，见第九节坑12）。
2. 手机和电脑连**同一个 WiFi**，防火墙放行 8080 入站。
3. HBuilderX 打开 `snake-aid-app` → 运行 → 运行到手机或模拟器（首次自动装标准基座）。
4. App 直连 `电脑IP:8080`，后端栈保持运行即可。

## 八、打包与部署

### 打安卓 APK

**完整手册见 [`docs/APK打包环境版本记录.md`](./APK打包环境版本记录.md)**——包含精确版本、逐步命令和 11 个已知坑。流程摘要：

```
① 同步源码到 5.26 模板环境（%TEMP%\uni-tpl-test，项目自带4.15不能用）
② npm.cmd run build:custom app-plus     编译 App 资源
③ 校验产物里的地址与 api.js 的 APP-PLUS 值一致（当前为 localhost:8080）
④ robocopy 拷入 Android 工程（HBuilder-Integrate-AS）
⑤ 设 JAVA_HOME=HBuilderX 自带 corretto17 → gradlew assembleRelease
⑥ 产物: simpleDemo\build\outputs\apk\release\simpleDemo-release.apk
```

APK 内的后端地址在**编译时写死**——换服务器/换 IP 必须重新走 ①②④⑤。

### 部署到服务器（deploy/deploy-102.sh）

针对「一台没有外网的 Linux 服务器」的离线方案，思路：

```
本机 docker save 导出 4 个镜像 → scp 传到服务器 → docker load 导入
Docker .deb 包离线安装 → systemctl enable docker（开机自启）
compose 的 restart: unless-stopped（容器开机自启）→ docker compose up -d
```

脚本七步幂等（重复执行安全），自带**端口占用预检**（8080/8081/3307/6379 被占就打印占用者并中止，不动机器上原有服务）。在服务器上执行：

```bash
sudo bash /opt/snakebite-first-aid/deploy/deploy-102.sh
```

## 九、常见坑速查表（全部是本项目真实踩过的）

| # | 现象 | 原因与对策 |
|---|---|---|
| 1 | `npm` 报 `cannot be loaded because running scripts is disabled` | PowerShell 执行策略禁 `.ps1`。**一律用 `npm.cmd`** |
| 2 | App 打包产物是 H5 格式/接口全不对 | 项目自带 **4.15 编译器对 app-plus 平台静默降级**。必须走 5.26 模板环境（见打包手册） |
| 3 | gradle 报 `JAVA_HOME is not set`，但"看起来构建了" | 新终端没有 JAVA_HOME。构建前设 `$env:JAVA_HOME="C:\software\HBuilderX\plugins\amazon-corretto"`（JDK17）。**别用 Android Studio/DataGrip 的 JBR——那是 JDK25，AGP 8.7.3 不认** |
| 4 | robocopy 后 PowerShell 报错"退出码1" | robocopy **退出码 0~7 都是成功**，≥8 才是失败 |
| 5 | App 端打包报全局组件错误 | `App.vue` 里全局组件必须**静态 import**（`import X from '@/components/X.vue'`），不能异步函数式导入 |
| 6 | 手机报"未配置appkey或配置错误" | DCloud 离线打包必须配 appkey：`AndroidManifest.xml` 的 `dcloud_appkey`（申请见 DCloud 开发者后台） |
| 7 | 真机请求报 `CLEARTEXT_NOT_PERMITTED` | Android 9+ 禁明文 http。需在原生 `AndroidManifest` 开 `usesCleartextTraffic`（当前 targetSdk 33 的基座未开就中招） |
| 8 | 改了 `manifest.json` 后 appid 异常 | 文件必须存成 **UTF-8 无 BOM**（VS Code 右下角确认） |
| 9 | `%TEMP%` 里的 uni 模板环境突然没了 | 系统清理临时文件会连 node_modules 一起删，需重建（打包手册坑10） |
| 10 | curl/请求莫名超时但服务明明是好的 | ① PowerShell 的 `Invoke-WebRequest` 会走系统代理——验证一律用 `curl.exe`；② 沙箱环境会挡 Docker/网络命令，Docker 相关操作可能需要退出沙箱执行 |
| 11 | 管理台 502 | `nginx.conf` 的 `proxy_pass` 被改成了非 `snake-backend` 的地址（见第六节） |
| 12 | App 连不上后端 | 依序检查：① `api.js` 的 APP-PLUS 地址——默认 `localhost` 在手机上指的是**手机自己**，必须改成电脑的局域网 IP（`ipconfig` 查；WiFi 断线会变成 169.254 无效地址）；② 手机和电脑是否同 WiFi；③ 防火墙是否放行 8080 入站（仅 192.168.1.0/24）；④ `docker compose ps` 容器是否 healthy |
| 13 | 端口被占用起不来 | `netstat -ano | findstr :8080` 找占用者；compose 改端口映射即可（MySQL 已绑回环不冲突） |

## 十、新手实战：如何加一个新功能（端到端示例）

假设需求：**新增「蛇伤案例库」页面 + 接口**。

### 第 1 步：数据库（可选，有新表时）

在 `snake-aid-backend/docs/sql/` 新增或追加 `CREATE TABLE snake_case (...)`，然后手动执行（init 只在空库跑一次）：

```powershell
Get-Content your.sql -Raw | docker exec -i snake-mysql mysql -uroot -proot123456 snake
```

### 第 2 步：后端（4 个文件，按层往下写）

```
entity/SnakeCase.java        实体类，字段=表字段
mapper/SnakeCaseMapper.java  继承 BaseMapper<SnakeCase>，单表 CRUD 直接有了
service/SnakeCaseService.java + impl/   业务方法（简单 CRUD 可省略直接调 mapper）
controller/app/SnakeCaseAppController.java   @RestController @RequestMapping("/case")
    写 @GetMapping("/list") 返回 Result.ok(...)
```

### 第 3 步：管理台（2 个文件）

```
src/api/case.js        export function fetchCases(){ return request.get('/case/list') }
src/views/CasePage.vue 页面组件，调用上面的 api
（路由在 router 配置里注册，侧边栏菜单加入口）
```

### 第 4 步：手机端（2 个文件 + 1 次注册）

```
pages/case/list.vue    import { API_BASE } from '@/utils/api'
                       const res = await fetch(`${API_BASE}/case/list`)
pages.json             "pages" 数组里注册 { "path": "pages/case/list", ... }
```

### 第 5 步：验证

```powershell
docker compose up -d --build backend     # 后端改了要重建
# 打开 http://localhost:8080/api/doc.html 能看到新接口并试调
docker logs snake-backend                 # 看 SQL 是否执行
```

**要点**：手机端地址永远只写 `API_BASE` 拼接，**绝不写死 IP**——环境切换就改 `utils/api.js` 一处。

## 十一、常用命令速查


## 附：改代码前的三个习惯

1. **`git status` 先看一眼**——了解当前工作区有哪些未提交改动，改完知道自己动了什么。
2. **改完先跑再提交**——H5 改动浏览器刷新即生效；后端改动要 `compose up -d --build backend`；改了 `utils/api.js`/`manifest.json` 记得三种运行方式（H5/App/管理台）影响面不同。
3. **地址类改动只碰开关文件**——服务器地址改 `utils/api.js`（+ H5 代理的 `vite.config.js`/`manifest.json`），nginx 反代改 `snake-admin-web/nginx.conf`，端口/密码改 `docker-compose.yml`。不要在页面里散落硬编码。
